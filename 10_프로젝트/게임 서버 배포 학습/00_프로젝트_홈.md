# 게임 서버 배포 학습

## 목표

게임 서버 프로젝트의 변경 사항이 실제 서버 프로세스로 실행되기까지의 흐름을 기술 간 관계로 설명할 수 있게 된다.

> 코드 변경 → TeamCity 빌드 → Docker 이미지 생성 → Harbor 저장 → Helm values 변경 → ArgoCD 동기화 → Kubernetes 배포

명령어 암기보다 각 도구가 무엇을 입력받고 무엇을 만들어 다음 단계에 넘기는지 이해하는 데 집중한다.

이 프로젝트에서는 배포를 컨테이너 하나의 실행 문제로만 보지 않는다. **서버 바이너리, 설정, 에셋, DB 스키마가 서로 다른 경로로 전달된 뒤 하나의 호환되는 릴리스로 만나는 과정**까지 학습 범위에 포함한다.

## 진행 방법

1. 한 번에 한 단계의 문서만 읽는다.
2. 문서 끝의 확인 질문에 자신의 말로 답한다.
3. 이해되지 않은 부분은 질문하고 문서에 보충한다.
4. 사용자가 이해했다고 확인하면 다음 단계 문서를 만든다.

현재 단계는 [[06_Service와_네트워크]]다. 이전 단계는 [[05_Pod_Deployment_ReplicaSet]]이다.

## 학습 범위를 보는 관점

《쿠버네티스 교과서》는 Kubernetes 플랫폼의 넓은 기능을 다룬다. 이 학습 프로젝트는 그중 실제 애플리케이션 배포를 이해하는 데 필요한 부분을 먼저 배우고, 책에서 상대적으로 덜 다루는 실무 도구를 보완한다.

| 범위 | 이 프로젝트의 판단 |
| --- | --- |
| Docker, Pod, Deployment, Service, 설정, 볼륨 | 배포를 이해하기 위한 필수 기초 |
| Harbor, Helm, ArgoCD, GitOps, Argo Rollouts | 실제 배포 흐름에서 중요하므로 필수 보완 |
| 빌드 버전, 에셋, DB migration, 배포 순서 | Kubernetes 밖에서 움직이지만 하나의 릴리스를 이해하려면 필수 |
| 로그, 모니터링, probe, 리소스 관리 | 배포 성공 판정과 장애 조사에 필요한 운영 기초 |
| 클라우드별 클러스터 구축, Operator 직접 작성, 서버리스, 고급 정책 | 핵심 흐름을 완주한 뒤 선택 학습 |

일반적인 웹 애플리케이션 예제와 게임 서버의 차이도 계속 확인한다.

- HTTP Ingress보다 서버 간 통신과 TCP 연결이 더 중요할 수 있다.
- GameWorker 복제는 세션, 채널, 상태 소유권 때문에 웹 서버 복제보다 제약이 많다.
- 프로토콜이나 DB 계약이 바뀌면 구버전과 신버전의 동시 실행이 위험할 수 있다.
- 항상 Rolling Update가 정답은 아니며, 전체 정리 후 동일 리비전으로 기동하는 편이 안전한 경우도 있다.

## 현재 확인 범위

- 로컬 서버·빌드 소스와 사내 개발용 Kubernetes 배포 구성을 근거로 학습한다.
- 실제 라이브 환경의 저장소, 비밀 관리, 관측 시스템, probe 구성은 아직 확인되지 않았다.
- 저장소 밖의 TeamCity UI 설정과 인프라 운영 정책도 `외부 확인 필요` 영역이다.
- 사내 개발 환경에서 확인한 구조를 라이브 환경의 사실로 확대 해석하지 않는다.

## 선택·심화 과정

핵심 흐름을 완주한 뒤 필요에 따라 학습한다.

- 멀티 노드 클러스터와 클라우드 Kubernetes
- Ingress, HTTPS, NetworkPolicy, SecurityContext
- 고급 RBAC, Admission 정책, Operator
- 자동 스케일링과 고급 스케줄링
- Argo Rollouts 고급 전략
- StatefulSet 기반 데이터 시스템과 클러스터 자체 운영

## 공개용 표기 원칙

- 실제 프로젝트명 대신 `게임 서버 프로젝트`라고 쓴다.
- 실제 프로세스명 대신 역할을 나타내는 `ControlServer`, `GameWorker`, `GatewayServer`를 쓴다.
- 실제 저장소명, 이미지 주소, 호스트명, 파일명은 기록하지 않고 역할명이나 `<자리 표시자>`로 바꾼다.
- 구조와 동작은 로컬 프로젝트에서 확인하되 공개 문서만 읽어서는 내부 식별자를 복원할 수 없게 한다.

보안상 인증 정보와 민감한 설정값은 학습 문서에 기록하지 않는다. 로컬 소스에서 확인하지 못했거나 배포 저장소 확인이 필요한 세부 사항은 추측하지 않고 `검증 필요`로 표시한다.

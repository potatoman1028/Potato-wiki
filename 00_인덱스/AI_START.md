# AI_START — 개인 위키 공용 작업 규칙

> 이 문서는 사람, Codex, Claude가 함께 사용하는 위키 운영 규칙의 원본이다. 이 저장소는 공개 GitHub 저장소이므로 모든 변경은 공개될 수 있다고 가정한다.

## 작업 시작

1. [[HOME]]에서 위키 구조와 현재 인덱스를 확인한다.
2. 요청과 관련된 기존 노트와 인덱스를 먼저 읽는다.
3. 기존 문서를 갱신할 수 있으면 비슷한 새 문서를 중복 생성하지 않는다.
4. 분류가 불명확한 빠른 기록은 [[INBOX]]에 둔다.

## 문서 위치

| 위치 | 내용 |
| --- | --- |
| `00_인덱스/` | HOME, INBOX, 주제별 진입점 |
| `10_프로젝트/` | 목표와 완료 조건이 있는 진행형 작업 |
| `20_영역/` | 지속적으로 관리하는 생활·업무 영역 |
| `30_지식/` | 재사용할 개념, 원칙, 문제 해결법 |
| `40_자료/` | 책, 글, 영상 등 출처 기반 기록 |
| `90_보관/` | 완료되었거나 현재 사용하지 않는 문서 |
| `98_템플릿/` | 문서 템플릿 |
| `99_첨부/` | 이미지와 첨부파일 |
| `99_비공개/` | Git에서 제외되는 로컬 전용 기록 |

## 작성 규칙

- 기본 언어는 한국어로 한다. 고유명사와 기술 용어는 필요하면 원문을 병기한다.
- 기존 문서의 YAML frontmatter와 문체를 보존한다.
- 새 노트에는 최소한 `type`, `created`, `updated` 속성을 둔다.
- 문서를 수정하면 `updated`를 실제 수정일로 갱신한다.
- 관련 문서는 Foam 위키링크 `[[문서명]]`으로 연결한다.
- 새 문서를 만들면 적절한 인덱스 문서에도 링크를 추가한다.
- 폴더 깊이는 필요 이상으로 늘리지 않는다.
- 대규모 이동, 이름 변경, 통합, 삭제는 먼저 사용자에게 범위와 영향을 알리고 승인받는다.
- 파일 이름을 변경하거나 이동하면 기존 위키링크가 깨지지 않았는지 확인한다.
- 확인되지 않은 내용은 사실처럼 쓰지 않고 `검증 필요`로 표시한다.

## 독서 기록

- 긴 독서 기록은 `한 권 = 폴더`, `한 장 = Markdown 파일`을 기본으로 한다.
- 책 폴더에는 `00_책_홈.md`, 목차별 노트, 필요하면 `99_완독_회고.md`를 둔다.
- 저자의 주장과 목차별 요약은 `40_자료/`에 둔다.
- 여러 상황에 재사용할 수 있도록 다시 정리한 생각은 `30_지식/`에 별도 노트로 만들고 원본 독서 노트와 연결한다.
- 공개 저장소에 책 원문을 길게 전재하지 않는다. 인용은 필요한 만큼만 짧게 쓰고 가능하면 페이지를 기록한다.

## 공개 저장소와 개인정보

- 비밀번호, API 키, 토큰, 인증 정보, 개인 식별 정보는 기록하지 않는다.
- 공개하기 어려운 내용은 커밋하지 않는다. 사용자가 명시적으로 요청한 경우에만 `99_비공개/`에 로컬 기록을 만든다.
- `.trash/`, 운영체제 임시 파일, 로컬 비공개 메모 등 기기별·비공개 상태 파일을 추적하지 않는다.
- 외부 링크나 자료를 추가할 때 출처를 함께 기록하고, 사실과 개인 의견을 구분한다.

## Git 작업

- 문서 작성과 Git 커밋·푸시는 별개의 작업으로 취급한다.
- 사용자가 명시적으로 요청하지 않으면 커밋하거나 푸시하지 않는다.
- 강제 푸시, 이력 재작성, 대량 삭제는 하지 않는다.
- 변경 전후로 현재 작업 트리 상태를 확인하고 사용자 변경을 덮어쓰지 않는다.

## 완료 확인

1. frontmatter 날짜와 문서 위치가 맞는지 확인한다.
2. 새 문서가 적절한 인덱스에 연결되었는지 확인한다.
3. 위키링크와 Markdown 형식이 깨지지 않았는지 확인한다.
4. 공개 저장소에 부적절한 정보가 포함되지 않았는지 확인한다.
5. 변경한 파일과 남은 작업을 사용자에게 간단히 보고한다.
